# Стратегия работы с 600 MB PDF

## Главный вопрос: могу ли я работать с этим файлом?

Не напрямую. Технически у меня есть `Read` для PDF, но:

- лимит — 20 страниц за один вызов (тут как раз 15, влезает),
- но **600 MB на 15 страниц = ~40 MB на страницу**, это значит, что страницы — это огромные растры, и попытка прочитать их через Read почти наверняка либо упадёт, либо съест весь контекст с одной страницы.

Поэтому нужен offline-препроцессинг файла **до** того, как я его трогаю.

## Что внутри PDF (гипотезы)

Создан через `pdf-lib`. ReadyMag, скорее всего, рендерит каждую страницу сайта в один длинный растровый снапшот и заворачивает в PDF. То есть это не векторный документ с настоящим текстом, а серия больших картинок. Подтверждение: средний размер страницы ~40 MB — типичная высокая JPEG растровка длинной страницы.

Это значит, что:

- `pdftotext` даст мало или ничего,
- `pdfimages -all` извлечёт 1-2 больших растра на страницу,
- настоящий контент (тексты, ссылки, виджеты) лучше брать из HTML-сниппетов ReadyMag, а не из PDF.

## Рекомендуемая обработка PDF до того, как я его читаю

1. Поставить локально poppler и/или mupdf:

   ```sh
   brew install poppler mupdf
   ```

   Это даст: `pdfinfo`, `pdftotext`, `pdfimages`, `pdftoppm`, `pdftocairo`, `mutool`.

2. Получить мету:

   ```sh
   pdfinfo redymag-pdf-site2020/PdfExport-*.pdf
   ```

3. Разбить на отдельные страницы (PDF):

   ```sh
   mkdir -p redymag-pdf-site2020/pages
   pdfseparate redymag-pdf-site2020/PdfExport-*.pdf \
     redymag-pdf-site2020/pages/page-%02d.pdf
   ```

4. Извлечь все вложенные изображения:

   ```sh
   mkdir -p redymag-pdf-site2020/images
   pdfimages -all -j -p redymag-pdf-site2020/PdfExport-*.pdf \
     redymag-pdf-site2020/images/page
   ```

5. Сделать compact preview каждой страницы (PNG, ширина 1200):

   ```sh
   mkdir -p redymag-pdf-site2020/previews
   pdftoppm -png -r 100 -scale-to-x 1200 -scale-to-y -1 \
     redymag-pdf-site2020/PdfExport-*.pdf \
     redymag-pdf-site2020/previews/page
   ```

6. Извлечь текст (на всякий случай, скорее всего пусто):

   ```sh
   pdftotext -layout redymag-pdf-site2020/PdfExport-*.pdf \
     redymag-pdf-site2020/extracted.txt
   ```

После этого я могу:

- читать `previews/*.png` как маленькие изображения для визуального контроля,
- сравнивать `images/*.jpg/png` с `parse-1/assets/*` и понимать, где у PDF растры выше качества, чем на CDN,
- использовать `extracted.txt`, если в нём что-то есть.

## Если ставить poppler/mupdf нельзя

Альтернативы:

- node-пакет `pdfjs-dist` или `mupdf-js`: в `scripts/` написать утилиту, которая сама разрежет PDF на страницы и вытащит изображения. Минус: медленнее и шумнее.
- WSL/Docker контейнер с poppler.
- Веб-сервис тоже не вариант: 600 MB не загрузишь, и это всё-таки чужие фотографии.

## Роль PDF в общей картине

PDF полезен:

- как **резервный источник**, если ReadyMag CDN отключат раньше, чем мы успеем перевезти сайт,
- как способ **сверить полноту**: каждая страница сайта = одна страница PDF, и порядок виджетов тот же,
- как **возможный источник чуть более крупных растров**, если ReadyMag-CDN отдаёт уменьшенные версии,
- **не как первичный источник текста и структуры**.

Первичные источники:

1. HTML-сниппеты ReadyMag (через парсер).
2. Оригиналы фотографий от Сергея (если он их пришлёт).
3. PDF — только как страховка и второй взгляд.

## Что не делать

- Не пытаться открывать весь 600 MB PDF в редакторах или браузере без подготовки.
- Не коммитить его в git как есть — нужен отдельный bucket / git-lfs / archived storage.
- Не строить сайт из PDF-извлечённых изображений: они ужаты под печать и могут потерять цвет.
