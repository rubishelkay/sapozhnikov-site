## Что это значит для стека

- **Astro**, без Tailwind (по согласованной рекомендации GPT — добавлять только отдельным решением).
- **Plain CSS** или CSS-модули внутри Astro-компонентов. Дизайн-токены — через CSS-переменные, готовим место под темы.
- **Output: static**, никакой server-side. `npm run build` → папка `dist/` с готовыми HTML/CSS/JS/images. Эту папку можно класть на любой статик-хостинг или на Яндекс.Диск + nginx.
- **Без CMS**, без headless-редактора, без баз. Контент — Astro-страницы (`.astro`) + MDX для длинных проектов.
- **Изображения**: в `/site/public/images/` (без runtime-оптимизации). На первой фазе оставляем как есть с ReadyMag качества; позже можно прогнать через `sharp` в build-time, но только если это не ломает «закинул и работает». Для сложного оптимизатора нужен Node на хостинге, а это нам не нужно.
- **Без `next/image`-стиля magic**: только обычные `<img>` с фиксированным `width/height`. Прозрачно для LLM-редактирования.
- **YouTube embeds** — обычные `<iframe>`, lazy через `loading="lazy"`, никаких внешних JS-библиотек.

2. Темы (auto / dark / light) с переключателем и `prefers-color-scheme`.
3. Новые проекты после 2020 года, включая ГЭС-2 «Дом и сад» (2023).
4. Многоязычность с переключателем (если решим выходить за пределы ru+en).
5. Раздел `/books/` поверх локально захостенных PDF-каталогов.
6. Лёгкий image-pipeline (sharp) для AVIF/WebP при build-time, если общий вес derived останется под контролем.
7. Контактная форма (если понадобится поверх mailto).
8. Аналитика (Plausible/Umami/Cloudflare Analytics, по выбору).
