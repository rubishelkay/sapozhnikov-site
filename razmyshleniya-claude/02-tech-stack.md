# Стек

## Контекст

Сайт — портфолио художника-фотографа: длинные страницы проектов, ~424 изображения, 10 видео, тексты на русском и английском, минимум интерактивности, обновляется редко. Обновлять будет один человек (Сергей) или мы вдвоём через git.

## Кандидаты

### 1. Next.js (App Router) + React Server Components

Плюсы:
- встроенный `next/image` с авто-AVIF/WebP, lazy, blur placeholder,
- ISR/SSG для статики, динамика на будущее (если будет CMS, контактная форма),
- огромная экосистема, легко найти подрядчика,
- удобно деплоится на Vercel, можно и на Cloudflare через `@cloudflare/next-on-pages`.

Минусы:
- более тяжёлый рантайм, чем нужно для статики,
- придётся следить за версиями (Next, React) каждые полгода,
- `next/image` оптимизирует на лету; для портфолио из 400 фото лучше предсборка.

### 2. Astro + чуть-чуть React/Svelte где надо

Плюсы:
- вся страница — статический HTML по умолчанию, JS только там, где явно нужен (`client:load`),
- встроенный `<Image>` с pre-optimized AVIF/WebP/JPEG, responsive `srcset`,
- `content collections` хорошо ложатся под "Projects → MDX",
- bundle минимален, идеально для портфолио,
- легко деплоится на любой статик-хостинг.

Минусы:
- меньше React-привычки, если ты много работал в Next.

### 3. Eleventy / Hugo / 11ty

Плюсы: ультра-лёгкий, ультра-быстрый, проще всего поддерживать.
Минусы: меньше "современный feel", меньше DX-удобства, чем Astro.

## Рекомендация

**Astro** — лучший вариант под этот сайт:

- портфолио = 99% статика → Astro идеален,
- встроенная оптимизация изображений из коробки лучше, чем в Next без доп. настройки,
- `content collections` + MDX дают почти-CMS опыт без CMS,
- легко мигрировать в Next позже, если появится backend,
- bundle ~ нескольких килобайт JS на страницу, что уважительно к фотографиям.

Если ты твёрдо хочешь Next.js (привычка / будущий backend / shadcn/ui):
- бери App Router + RSC,
- статика через `output: 'export'` или `next build` + Vercel,
- для изображений предсборка AVIF/WebP в `public/` через свой скрипт, а не `next/image` runtime, иначе на 400 фото получишь дорогие image transforms.

## Дополнительно к стеку (любому)

- **TypeScript** — да.
- **Tailwind CSS** — для скорости вёрстки. Темы (dark/light) — опционально.
- **MDX** — для текстов проектов с inline-картинками.
- **Sharp** (через `astro:assets` или свой скрипт) — для пересборки JPEG → AVIF/WebP в нескольких размерах.
- **Playwright** — для регрессионных скриншотов (один раз сделаем для каждой страницы и будем сравнивать при изменениях).
- **i18n**: на сайте смешаны русский и английский (например, `the_city` — длинный русский текст, остальные часто на английском). Astro и Next оба поддерживают i18n, но для портфолио проще иметь один язык на проект и переключатель только на About / Contacts.

## Backend — нужен?

Скорее всего, нет:

- комментариев нет,
- покупок/каталога нет,
- контактная форма решается mailto или Formspree/Resend без своего сервера,
- newsletter (если захочется) — Buttondown/Substack/Ghost newsletters, тоже без своего бэка.

Если в будущем появится:
- "купить отпечаток" → Stripe + Resend, серверная функция на Vercel/Cloudflare Workers,
- Архив/каталог с фильтрами → можно держать всё в JSON и делать фильтрацию на клиенте; SQLite/Turso только если каталог разрастётся выше 10k записей.

## CMS — нужен?

Сейчас — нет. MDX-файлы в репо + git это и есть CMS.

Если в будущем Сергей захочет редактировать сам без git:
- **Sanity** или **Contentful** — для проектов,
- **Decap CMS** (бывший Netlify CMS) — git-based GUI, бесплатно,
- **Tina CMS** — тоже git-based, удобный визуальный редактор.

Стартовать без CMS, добавлять только если попросит.
